# new-api 原生状态页与降智检测：实施与部署说明

日期：2026-10-27。项目及归属保持 new-api / QuantumNous 不变。

本轮是首轮代码实现，不是生产上线或完整设计验收。检测调度、公开状态页和样本发布默认关闭；开发验证只使用本地可控上游，不调用真实模型。Cloudflare Rocket Loader 按已确认决定由部署方关闭，本次没有添加兼容脚本。

## 已实现的路径

- `/quality-detection` 管理工作台：渠道唯一检测配置、不可变提示词版本、手动批次、取消、分页记录、样本纯文本、人工复核和基线操作。
- 持久化批次按渠道去重，同一轮的渠道结果供多个真实分组共享。手动幂等键、活动任务约束和数据库租约共同限制重复执行。
- 后台指定渠道直接调用 API，复用模型映射、凭据和适配器；不启动 Codex CLI，不进入客户钱包、订阅结算、业务消耗日志和生产渠道启停流程。
- 执行前预留 UTC 日调用次数与 token 预算：冻结提示词的 UTF-8 字节数、输出上限，再加 512 token 的协议封装余量。缺失 usage、流中断或失锁后保留不确定用量的预留；不自动重试、跟随重定向或重放生成。
- 发送前重新核对当前渠道与检测配置。渠道检测被停用，或模型、提示词、协议、推理强度、有效超时和输出上限发生变化时跳过，不改用新配置发送；未发送的预留会释放。公开别名及发布范围的修改不使冻结请求失效。
- `/status` 展示明确发布的真实分组，支持筛选、排序、分页、详情、共享截图和样本新鲜度。业务趋势只使用数据库闭合时间桶，按原始计数加权；无数据保持 null。
- 公共产物仅为受控 PNG，每次读取重新检查当前发布范围。管理员 HTML 作为纯文本附件返回，不在主站执行。
- 导航、概览和设置切换到原生状态数据。旧 `/api/uptime/status` 从本次版本起返回 410，不再外呼 Kuma；旧设置保留用于回滚，不自动迁移为公开分组。
- 可选截图组件位于 `tools/quality-renderer/`，与 Go 主服务分离。截图失败不覆盖已完成的模型生成结果。

接口以 [quality-detection-api.md](quality-detection-api.md) 和 [独立 OpenAPI](../openapi/quality-detection.json) 为准。

## 当前实现边界

1. 仅接入 OpenAI/Azure 的 Chat Completions、Responses 和 Anthropic 的 Claude Messages 文本协议。其他渠道类型显示不支持。原生 Codex 适配器会移除输出 token 上限，当前未接入，不能把它视为已支持。
2. 已实现有界输出收集、协议正常结束校验、HTML 提取及静态规则证据（外部资源引用、内置按钮预设要求的元素）。静态扫描不等于完整网络行为验证；真实浏览器交互规则和连续计划轮次的退化判断尚未实现。生成完成的样本保守标记 `needs_review`。人工接受/拒绝独立保存，不伪造 `rules_passed`、模型身份或智力分数。
3. 工作台支持当前样本与已引用基线的静态图片比较；渲染环境与关键参数变化后的完整自动可比性判定仍需完善。截图不证明按钮、动画或其他交互正确。
4. 当前历史列表按批次分页；设计中的完整多维历史筛选、独立预算剩余概览、默认提示词管理和公开分组历史浏览尚未全部实现。
5. token 预算是运维准入限制，不是精确上游账单。输入按冻结文本及协议开销保守预留，输出按发送的上限预留；最终取可信 usage。兼容上游不遵守限制时不能保证真实费用，需同时配置供应商侧限额。
6. 截图服务的 `renderer_available` 仅表示连接配置有效，不表示实时健康。无配置时允许保存生成结果，但没有缩略图。PNG 的保存与读取统一限制为 2 MiB；记录的 `new-api-quality-v1-pw1.64.1` 表示随项目提供的渲染版本，当前 Go 客户端没有验证远端返回的版本标识，不能把该字段当作远端运行环境证明。
7. SQLite 测试已覆盖核心持久化行为；MySQL/PostgreSQL 的实际迁移、并发事务、恢复和清理需要在目标版本实例上验收。
8. 当前机器 Docker Linux 引擎不可用，因此未完成镜像构建和真实 Chromium 沙箱、字体、网络隔离及截图验收。浏览器集成测试的跳过不是通过；不得为使其启动而关闭沙箱或放开网络。

## 启用顺序

1. 先备份数据库及原有配置，协调更新 Go 后端和前端。新表通过现有迁移入口创建。此次没有替用户部署或修改生产数据。
2. 配置 `QUALITY_ARTIFACT_DIR`。单机默认 `./data/quality`；多实例必须指向同一个受限共享目录，并纳入备份。数据库与产物应一起恢复，不能只恢复其一。
3. 需要截图时，按 [渲染组件 README](../../tools/quality-renderer/README.md) 部署独立鉴权入口与无网络浏览器工作容器。在目标 Linux 环境先通过实际浏览器集成验收，再配置主应用的 `QUALITY_RENDERER_URL`、`QUALITY_RENDERER_TOKEN`。令牌不进入前端设置或浏览器工作容器。
4. 管理员进入 `/quality-detection`，为明确支持的渠道选择一个文本模型、协议和提示词版本，并设置预算、并发及超时。渠道系统提示词、参数覆盖如果会改变冻结输入、目标模型或输出上限，检测会拒绝发送，而不是静默忽略。
5. 先手动运行小批次并核对：渠道 A 同属两个组、渠道 B 属于其中一个组时，只出现两条生成记录；A 在两个组引用同一公开样本。手动运行仍可能产生供应商费用，调度关闭不代表手动运行免费。
6. 人工检查原始文本、截图、usage、取消和失败分类后，再开启周期调度。关闭页面只停止页面查询；停止任务必须使用“停止批次”。关闭周期调度不会自动撤销正在运行的批次。
7. 单独选择要发布的分组和公开别名，允许对应渠道样本公开，然后开启状态页。发布范围不改变用户调用权限。撤销发布后重新读取公共详情与图片均应拒绝。
8. 确认 `/status`、控制台概览和旧 Kuma 地址的表现，检查业务统计截止时间。前端刷新、模型筛选和查看截图均不能新增模型调用。

## 回滚与保留

- 先关闭调度、取消运行批次，再撤销公开状态页。已发送的上游请求可能已收费，取消不能撤销费用。
- 保留新增表、产物目录和旧 Kuma 设置。回滚应用版本应协调前后端，并确认旧版本与新增数据库结构兼容；不要通过删除表实现回滚。
- 默认产物保留 14 天、普通历史元数据保留 90 天；当前基线及受引用样本受保护。保留策略不是严格磁盘容量配额，部署方仍需监控共享目录容量。

- 新增质量检测、原生状态、管理员权限及 Kuma 退役的针对性 Go 回归通过。
- `controller`、`model`、`router`、`relay/helper`、`relay/common`、`relay/channel` 全包测试通过；相关包 `go vet` 通过。

- 截图组件 22 项 Node 契约测试、语法/lint 和 Compose 配置检查通过。Go race 检查因本机 CGO 未开启而不可用。

- 全仓库 `go test ./... -run '^$' -count=1` 通过；该命令仅验证编译，不代表全量测试执行通过。
- 前端 28 项 UI 行为测试及 3 项配置校验测试通过；`typecheck`、涉及文件的 lint/format、生产构建及 `git diff --check` 通过，七语种同步报告的缺失键、多余键与未翻译计数均为 0。临时翻译与格式检查脚本已清理。
- 前端尚未进行真实后端联调及浏览器视觉验收；生产容器、真实模型及三库联合验收均不计为已完成。
